# http-example

Учебный HTTP-сервер Хекслета: [https://http.hexlet.app](https://http.hexlet.app). На него **живьём ходят студенты** из курсов HTTP API, протокол HTTP, Postman, js-playwright и курсов Selenium и Playwright, а уроки и самостоятельные работы цитируют его ответы дословно, вплоть до значений полей.

Отсюда главное свойство проекта: **ответы сервера это контент курса**, а не деталь реализации. Правка данных здесь делает неверным текст урока в другом репозитории, и по коду это не видно. Поэтому правила работы с проектом собраны в [AGENTS.md](./AGENTS.md), и читать их стоит до первой правки — там же разобрано, почему наборы данных такого размера, почему они не меняются и какие коды ответов несут уроки.

Устройство короткое: четыре спецификации на TypeSpec (`typespec/<app>/`, по одной на курс) компилируются в OpenAPI, а маршруты, валидацию и авторизацию строит из них `fastify-openapi-glue`. Руками написаны только данные и то, что в OpenAPI не выражается. Значит документация и поведение разъехаться не могут: студент читает ту же спецификацию, по которой работает сервер.

## Эндпоинты принадлежат курсам

Новый набор эндпоинтов добавляется под конкретный курс с собственным префиксом. У каждого курса свои адреса, данные и изменяемое состояние. Общий код обработчиков допустим при сохранении контрактов остальных курсов. Так изменение примера одного курса сохраняет ответы, которые уже используют другие уроки.

| Курс | Префикс | Данные |
| --- | --- | --- |
| HTTP API | `/http-api` | Фиксированные коллекции |
| Протокол HTTP | `/http-protocol` | Коллекции и примеры протокола |
| Postman | `/postman` | Фиксированные коллекции |
| JS Playwright | `/js-playwright` | Фиксированные коллекции |
| HTTP для автоматизации | `/http-for-automation` | Отдельные опыты с сессиями, кешем, вебхуками и ошибками |
| Автоматизация рабочих процессов | `/workflow-automation` | Динамические заказы отдельного учебного магазина |

Префиксы приложений для Selenium и Playwright перечислены ниже. При добавлении или изменении набора запускается полный `mise run check`, чтобы проверить контракты всех курсов.

## Магазин для автоматизации рабочих процессов

Страница `/workflow-automation` содержит описание API и кнопки создания магазина и получения заказов. Все его маршруты начинаются с `/workflow-automation`.

| Метод и путь | Результат |
| --- | --- |
| `POST /shops` | Новый магазин, его `shop_id`, относительный `orders_url` и `expires_at` |
| `GET /shops/{shop_id}/orders?after=0` | Три новых заказа, `next_after`, `through` и `has_more` |
| `GET /shops/{shop_id}/orders/{id}` | Уже созданный заказ без генерации новых данных |
| `POST /shops/{shop_id}/orders/{id}/process` | Подтверждение обработки оплаченного заказа |

Каждый новый опрос без `through` добавляет три заказа. Товары, количество, суммы и статусы меняются по последовательности заказов. У существующего заказа сохраняются ID, время создания, состав и сумма. Статус оплаты принимает значения `paid`, `pending` или `cancelled`. Подтверждение доступно только для `paid`, остальные статусы возвращают 409. Данные и названия товаров учебные, суммы указаны в рублях.

Первый опрос передаёт `after=0`. Для следующего опроса используется `after` из `next_after` предыдущего ответа. Для страниц меньше трёх заказов задаётся `limit` от 1 до 100. Пока `has_more` равно `true`, следующая страница передаёт полученные `next_after` и `through`. Параметр `through` фиксирует верхнюю границу текущей выборки и отключает генерацию. Это позволяет закончить обход и повторить страницу без появления новых заказов. Новый опрос начинается без `through`.

Для опыта с повтором к запросу обработки добавляется `?failure=before` или `?failure=after`. Первый вариант один раз возвращает 503 до изменения заказа. Второй один раз возвращает 503 после сохранения обработки. Оба ответа содержат `Retry-After: 1`. Повтор обработки возвращает тот же заказ с прежним `processed_at`, поэтому один заказ не обрабатывается повторно. Получение заказа отдельным GET позволяет проверить результат независимо от ответа обработки.

Магазин живёт 24 часа и хранит до 300 заказов, одновременно доступны 200 магазинов. При достижении лимита заказов новый опрос возвращает 429, чтение и обработка уже созданных заказов остаются доступны. При истечении срока или перезапуске сервера магазин исчезает и запрос возвращает 404. В этих случаях создаётся новый магазин. Данные хранятся в памяти и изолированы от других магазинов и префиксов курсов. Ответы имеют `Cache-Control: no-store`.

## Примеры форматов тела

Урок `body-formats` курса HTTP для автоматизации использует следующие адреса. Обработчики показывают полученные данные без сохранения задач.

| Метод и путь | Результат |
| --- | --- |
| `GET /http-protocol/form` | HTML-форма с полями `title` и `description` |
| `POST /http-protocol/form` | Полученные значения обоих полей обычным текстом |
| `POST /http-protocol/body` | JSON с заголовками запроса и данными в `json`, `form` или `files` |
| `GET /http-protocol/image.png` | Файл PNG размером 8090 байтов |

Обработчик `body` принимает JSON, `application/x-www-form-urlencoded` и multipart. Для примера с файлом он возвращает его содержимое как строку UTF-8. Лимиты multipart допускают один файл до 64 КиБ и до десяти текстовых полей по 4 КиБ. Исходное тестовое изображение взято из [httpbin](https://httpbin.org/image/png), который распространяется под [лицензией MIT](https://github.com/postmanlabs/httpbin/blob/master/LICENSE).

## Учебные приложения для UI-тестов

Курсы Selenium и Playwright тестируют маленькие приложения под префиксом своего курса. У каждого своя предметная область, и страницы в нём появились из её сценариев. Уроки ищут элементы и проверяют тексты дословно, поэтому локаторы и надписи этих страниц тоже контент курса.

**`/java-selenium`, библиотека City Library.** Курс разбирает действия пользователя, окна и фреймы, и у каждого действия в библиотеке есть смысл.

| `/java-selenium/covers` | обложки `.figure`, название `.figcaption h5` видно при наведении, двойной клик добавляет книгу в избранное |

| `/python-playwright/login` → `/staff` | вход сотрудника `agent` / `staff123`, «Passenger list», пассажиру отвечает 403 «Access denied» |
| `/python-playwright/login` | `blocked` / `flight123` заблокирован, пустые поля дают «Username is required.» и «Password is required.» |

| `/python-playwright/check-in` | форма регистрации: подписи, `select` и множественный `select`, кастомный список «Meal», radio, чекбоксы, загрузка файлов, теневой DOM; «Checked in» появляется через секунду |

| `/python-playwright/seat-map` | схема салона: двойной клик по «Summer trip» открывает поле «Group name», места `Seat 14A` выбираются кликом, Shift и Ctrl, правый клик даёт меню «Seat details», клик по canvas «Cabin overview» прокручивает список `cabin` к ряду, пассажиров перетаскивают на место, меню «View» раскрывается наведением |
| `/python-playwright/trace.zip` | трейс упавшего входа с неверным паролем для `playwright show-trace <адрес>`, отдаётся с `Access-Control-Allow-Origin: *` для trace.playwright.dev |

API курса лежит под тем же префиксом и набор данных не меняет. `GET api/departures` фильтруется параметром `status`. `POST api/login` отдаёт токен `<учётка>-token` и открывает сессию браузера. `api/bookings` закрыт заголовком `Authorization: Bearer <токен>`: GET списка и записи, POST отвечает 201 (без `flight` или `passenger` 422), PUT и PATCH отвечают изменённой записью, DELETE отвечает 204.

У всех трёх одинаковое устройство входа. Форма `#login` с полями `#username` и `#password` и кнопкой `button.primary[data-test=login-button]`, флеш-сообщение `#flash`, выход по `/<курс>/logout`. Приложения описаны конфигом `apps` в `custom-server/src/ui-pages.ts`, страницы лежат фрагментами в `custom-server/assets/ui-pages/<курс>/`, префикс в них записан как `{{prefix}}`.

## Демонстрации HTTP для автоматизации

Обработчики сессии, кеширования, событий и повторных запросов живут под префиксом курса `/http-for-automation`. Общие коллекции задач, пользователей и публикаций сохраняются.

| Метод и путь | Результат |
| --- | --- |
| `GET /http-for-automation/login-form` | Форма с учебным именем `student` |
| `POST /http-for-automation/session` | Куки `session=hexlet-demo` на пять минут |
| `GET /http-for-automation/session` | `Guest` без куки, `Welcome, student!` с учебной куки |
| `DELETE /http-for-automation/session` | Удаление куки клиента |
| `GET /http-for-automation/cache` | Расписание, `ETag` и `private, max-age=60` |
| `GET /http-for-automation/cache/revalidate` | То же расписание с `no-cache` |
| `GET /http-for-automation/cache/no-store` | То же расписание с `no-store` |
| `POST /http-for-automation/webhooks/inboxes` | Новый приёмник, его `callback_url` и `events_url` |
| `POST /http-for-automation/webhooks/inboxes/{id}/subscription` | Подписка с полученным `callback_url` |
| `POST /http-for-automation/webhooks/inboxes/{id}/trigger` | Отправка учебного события настоящим HTTP-запросом в свой приёмник |
| `GET /http-for-automation/webhooks/inboxes/{id}/events` | Сохранённые входящие сообщения и ответы приёмника |
| `POST /http-for-automation/reliability/runs` | Новый отдельный опыт с `run_id` и `base_url` |
| `GET {base_url}/temporary` | Первый ответ 503 с `Retry-After: 1`, следующий 200 |
| `GET {base_url}/limited` | 429 с `Retry-After: 1`, после ожидания 200 |
| `GET {base_url}/slow` | Ответ через две секунды для проверки таймаута |
| `POST {base_url}/operations?lose_response=1` | Создание операции с обрывом связи до ответа |
| `GET {base_url}/operations` | Результаты созданных операций |
| `GET {base_url}/journal` | Связь попыток с результатами операций |

Вебхуки принимают только подготовленные поля события. Подписка допускает приёмник этого же опыта, произвольные внешние адреса не вызываются. Реальный HTTP-запрос идёт на локальный порт приложения, за тем же публичным адресом. Получатель проверяет учебный `X-Webhook-Key: hexlet-demo-webhook` и подтверждает сохранение сообщения кодом 204. Этот общедоступный пример показывает форму проверки источника, настоящие учётные данные не используются.

При создании операции поле `title` обязательно. Если `Idempotency-Key` повторяется с тем же названием, сервер возвращает существующую операцию. Другое название под тем же ключом даёт 409. Без ключа каждый запрос создаёт отдельную запись. Параметр `lose_response=1` закрывает соединение после записи новой операции; уже найденная по ключу операция возвращается обычным ответом. При обращении через Caddy первый обрыв превращается в ответ 502 без результата операции. Это тоже оставляет клиенту задачу проверить, было ли изменение выполнено.

Приёмник и опыт живут 30 минут, данные хранятся только в памяти. Число опытов и размеры журналов ограничены. После истечения срока или перезапуска создаётся новый опыт. Фиксированный маркер сессии служит для демонстрации обмена куки, проверку настоящего аккаунта он не выполняет.

## Prerequisites

- [mise](https://mise.jdx.dev) (ставит Node, pnpm, Caddy и jactionlint по `mise.toml`)
- Docker (только для `compose:*`)

## Commands

```bash
mise run setup           # зависимости и компиляция спецификаций
mise run check           # типы, линтеры, сгенерированное, тесты
mise run test            # только тесты, против всех четырёх префиксов
mise daemons start       # приложение и Caddy на http://localhost:8080
mise run compose:build
mise run compose:up      # http://localhost:8080
```

Остальные задачи: `mise tasks`.
